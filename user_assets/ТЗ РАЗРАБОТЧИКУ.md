
## 1. Задача

Разработать интерактивную полноэкранную web-презентацию на тему:

> **«Первобытные люди и их стоянки на территории современной России»**

Презентация состоит из **7 полноэкранных сцен**, объединённых пространственными переходами.

Это **не scroll-site и не обычный PowerPoint**. Пользователь переключает смысловые экраны кнопками `← / →`.

Целевая среда:

- электронная доска;
    
- ноутбук + проектор;
    
- Chromium/Safari/Firefox;
    
- деплой на Vercel;
    
- преимущественно `16:9`.



```text
swipe left  = next

```

# 6. Navigation lock

Пока активен transition:

```ts
transitionLocked = true
```

Все дополнительные нажатия игнорируются.

После `onComplete`:

```ts
transitionLocked = false
```

Это обязательно, иначе пользователь двойным касанием сломает state.

---

# 7. Fullscreen

При `F`:

```ts
document.documentElement.requestFullscreen()
```

На электронной доске должно работать и без fullscreen.

Использовать:

```css
width: 100vw;
height: 100dvh;
overflow: hidden;
```

---

# 8. Aspect ratio

Основной дизайн — `16:9`.

Внутри окна создать виртуальный stage:

```ts
const scale = Math.min(
  window.innerWidth / 1920,
  window.innerHeight / 1080
)
```

Stage:

```css
width: 1920px;
height: 1080px;
transform: scale(var(--presentation-scale));
transform-origin: center;
```

Так все координаты storyboard остаются точными.

При несовпадающем aspect ratio допускаются узкие letterbox-поля.

**Не растягивать сцену по ширине независимо от высоты.**

# 15. Map implementation

Карту, линии и маркеры разработчик реализует самостоятельно.

Требования:

- SVG или GeoJSON → SVG;
    
- никакого Google Maps;
    
- никаких настоящих map tiles;
    
- минималистичный силуэт территории;
    
- 4 marker positions;
    
- labels;
    
- route может быть path.
    

Координаты хранятся в:

```ts
locations.ts
```

# 16. Map transition targets

Каждый site marker должен иметь стабильный DOM ref:

```text
#marker-kermek
#marker-denisova
#marker-kostenki
#marker-sungir
```

Для перехода использовать:

```ts
getBoundingClientRect()
```

а не magic pixel target.

Особенно важно для:

```text
02 → 03
06 → 07
```

# 17. SUNGIR → MAP

Критическое требование.

Для финальной анимации позиция центра burial-object должна интерполироваться к позиции `marker-sungir`.

Финальный frame:

```text
center(burialMorph) === center(markerSungir)
```

Погрешность максимум:

```text
2–3 px
```

на базовом `1920×1080`.

# 19. Performance

Цель:

```text
60fps desired
30fps minimum without visual breakage
```

Не анимировать:

```text
box-shadow
width
height
top
left
```

Анимировать:

```text
x
y

opacity
```

Через GSAP transforms.

`will-change` использовать только на реально движущихся элементах и снимать после transition.

# 21. Responsive behavior

Главная цель — электронная доска и desktop.

Для экранов меньше ~900 px:

- уменьшить navigation;
    
- canvas всё равно масштабировать;
    
- не перестраивать layout в мобильную колонку.
    

Это **презентация**, а не сайт для телефона.

# 23. Fallback mode

Добавить:

```ts
const lowMotion = false;
```

При проблемах производительности или `prefers-reduced-motion`:

- morph заменяется crossfade;
    
- camera zoom упрощается;
    
- content остаётся полностью доступным.
    

Например:

```text
06→07:
burial fade → map fade
```

вместо сложного radial morph.

# 28. Acceptance criteria

Работа считается готовой, если:

1. Есть **ровно 7 основных экранов**.
    
2. `← / →` крупные и работают с электронной доски.
    
3. Keyboard работает.
    
4. Нет browser scroll.
    
5. Ни одно двойное нажатие не ломает состояние.
    
6. Каждый экран можно открыть напрямую.
    
7. Назад приводит в HOLD предыдущего экрана.
    
8. `R` перезапускает текущую анимацию.
    
9. Hero → Map работает как zoom-out.
    
10. Map → Kermek работает как zoom-in.
    
11. Kermek → Denisova проходит через грунт.
    
12. Denisova → Kostenki визуально выходит к поверхности.
    
13. Kostenki → Sungir содержит короткий blackout.
    
14. Sungir → Final превращает погребение в точку Сунгиря.
    
15. AI-сцены имеют пометку «Художественная реконструкция».
    
16. Реальные материалы имеют источник.
    
17. На электронной доске нет мелких touch targets.
    
18. Нет заметных лагов при первом переключении.
    
19. После 07 существует финальный black state + restart.
    
20. Проект развёрнут на Vercel и работает после прямого reload URL.

```text

контент
← →
keyboard
preload
простые переходы
источники

```

**P1 — очень желательно:**

```text

02→03 zoom into marker
03→04 soil transition
04 vertical layer descent
06→07 burial→marker
```

**P2 — если остаётся время:**

```text
grain
ambient background drift
swipes
hidden menu
R replay
URL state
advanced masks
```

Если дедлайн горит, **не жертвуйте стабильностью ради morph-анимаций**. Семь идеально собранных экранов с четырьмя хорошими пространственными переходами будут выглядеть намного дороже, чем 25 нестабильных эффектов.
