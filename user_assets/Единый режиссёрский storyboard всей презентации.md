# 0. Как должна работать вся презентация

Формат — `1920×1080`, но вся композиция responsive `16:9`.

У презентации не должно быть обычного браузерного свободного scroll. Я бы сделал **controlled scroll / presentation mode**:

`Space / → / wheel down` — следующий beat.  
`← / wheel up` — предыдущий beat.

То есть презентация остаётся интерактивной, но ты никогда случайно не пролетаешь два экрана.

Каждая сцена имеет три состояния:

**ENTRY → HOLD → EXIT**

В `HOLD` камера почти неподвижна, и ты спокойно рассказываешь. Следующая команда запускает переход.

Общий motion language:

|Параметр|Правило|
|---|---|
|Камера|плавная, тяжёлая, без bounce|
|Основной переход|1.4–2.2 сек|
|Микроанимация текста|0.45–0.8 сек|
|Easing камеры|примерно `cubic-bezier(.65,0,.35,1)`|
|Easing текста|`ease-out`|
|Максимальный zoom|обычно не больше `1.35×`|
|Parallax|очень слабый: 2–6%|
|Blur|только во время быстрого перелёта, 2–6 px|
|Текст|opacity + движение максимум 12–24 px|
|Никаких|bounce, flip, 3D-card rotations, flying letters|
|Grain|постоянный едва заметный слой|
|Курсор|скрывать в presentation mode|

И главное: **фотографии почти не анимируются сами. Двигается камера относительно них.**

### Важный принцип реализации

Разработчик не должен пытаться сделать каждое движение «эффектным». Самые сильные переходы здесь всего четыре:

**пейзаж → карта**,  
**карта → Кермек**,  
**Кермек → земля → Денисова**,  
**Сунгирь → точка → карта**.

Остальные специально спокойнее. Если каждый экран будет делать сложный morph, презентация превратится в демо GSAP.
